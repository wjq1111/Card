# 登录系统设计文档

## 1. 目标

本文档定义 TexasHoldemOnline 的登录系统设计。这里的“登录”不是账号密码体系，而是玩家启动客户端后先确定自己的显示昵称，再进入大厅。

目标如下：

1. 打开游戏后先进入登录界面。
2. 默认生成用户名 `Playerxxx`。
3. 允许玩家自行输入用户名字符串。
4. 登录成功后进入大厅，而不是直接进入牌桌。
5. 为后续大厅、房间、断线重连保留清晰的会话入口。

## 2. 当前现状

当前版本中：

1. 客户端只有单一主界面。
2. 玩家输入服务器地址和昵称后，直接发送 `JoinRoom(room_id="lobby")`。
3. “连接服务器”和“进入房间”是同一个动作。

这会导致：

1. 没有独立登录态。
2. 无法自然承接大厅列表。
3. 后续扩展创建房间、加入房间时，状态切换会很混乱。

## 3. 设计范围

本设计只包含：

1. 登录界面。
2. 默认昵称生成。
3. 用户名输入和校验。
4. 登录成功后进入大厅的流程。
5. 登录相关的客户端状态和协议建议。

本设计不包含：

1. 房间列表。
2. 创建房间 / 加入房间。
3. 房间内准备、换座、开始游戏。
4. 账号密码系统。
5. 持久化账户和游客 token。

## 4. 用户流程

### 4.1 启动流程

1. 客户端启动后显示登录界面。
2. 自动填充服务器地址。
3. 自动生成默认用户名 `Playerxxx`。
4. 玩家可直接点击“进入大厅”，也可手动修改用户名后再进入。

### 4.2 用户名规则

建议规则：

1. 去除首尾空格后不能为空。
2. 长度限制为 1 到 24 个字符。
3. 允许中文、英文、数字和常见符号。
4. 服务端保留最终校验权。

默认用户名建议：

1. 格式为 `Player` + 三位或四位随机数。
2. 默认值只在客户端初次进入登录界面时生成一次。
3. 玩家手动修改后，不再自动覆盖。

### 4.3 登录成功流程

1. 玩家点击“进入大厅”。
2. 客户端完成本地校验。
3. 建立与服务端的长连接。
4. 客户端发送登录请求，仅声明“我是谁”。
5. 服务端返回登录成功事件与 `player_id`。
6. 客户端切换到大厅界面。

## 5. 客户端界面设计

### 5.1 页面状态

建议在客户端上层引入独立页面状态：

1. `LOGIN`
2. `LOBBY`
3. `ROOM`

登录系统只负责从 `LOGIN` 切换到 `LOBBY`。

### 5.2 登录界面布局

建议布局：

1. 游戏标题
2. 服务器地址输入框
3. 用户名输入框
4. 进入大厅按钮
5. 状态提示文本

交互要求：

1. 回车可触发登录。
2. 输入框支持鼠标选中和键盘输入。
3. 用户名为空时，点击按钮给出错误提示，不发送请求。
4. 登录过程中按钮短暂禁用，避免重复发送。

### 5.3 登录失败反馈

需要支持以下提示：

1. 用户名非法
2. 服务端连接失败
3. 登录请求超时
4. 服务端拒绝登录

提示方式建议：

1. 保留当前状态栏风格。
2. 错误文本使用高对比度红色或橙色。

## 6. 协议设计建议

当前协议把“连接后直接加入房间”绑定在一起。建议拆分为“登录”和“加入房间”两个阶段。

### 6.1 建议新增客户端事件

1. `Login`

字段建议：

1. `name`

### 6.2 建议新增服务端事件

1. `LoginAccepted`

字段建议：

1. `player_id`
2. `player_name`
3. `reconnect_token`

### 6.3 行为建议

1. 登录成功后，客户端处于“已连接大厅、未进入房间”的状态。
2. 登录请求不应隐式创建房间，也不应默认进入 `lobby` 房间。
3. `player_id` 由服务端分配，并作为后续大厅和房间操作的身份标识。

## 7. 客户端状态管理建议

登录系统需要新增或明确以下状态：

1. `player_name`
2. `player_id`
3. `reconnect_token`
4. `connection_state`
5. `ui_state`
6. `login_error_message`

建议状态切换：

1. 启动时：`DISCONNECTED + LOGIN`
2. 点击登录中：`CONNECTING + LOGIN`
3. 登录成功：`CONNECTED + LOBBY`
4. 登录失败：`DISCONNECTED 或 ERROR + LOGIN`

## 8. 验收标准

满足以下条件即可视为登录系统完成：

1. 客户端启动后先看到登录界面。
2. 用户名输入框默认显示 `Playerxxx`。
3. 玩家可以自行修改用户名。
4. 空用户名不会发起登录。
5. 登录成功后进入大厅，而不是直接进入房间。
6. 登录失败时有明确的可见错误提示。

## 9. 推荐结论

推荐把登录系统定义为“进入大厅前的轻量身份确认层”，而不是完整账号系统。这样改动最小，也能把当前“连接即进房间”的结构拆开，为后续大厅和房间系统打好边界。
