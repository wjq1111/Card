# 大厅与房间系统设计文档

## 1. 目标

本文档定义 TexasHoldemOnline 的大厅与房间系统设计，覆盖大厅列表、房间创建与销毁、加入房间、房主机制、准备机制、开始游戏倒计时，以及客户端文字清晰度改造。

目标如下：

1. 登录后进入大厅列表。
2. 大厅提供刷新按钮，拉取最新房间列表。
3. 服务端支持创建房间、销毁房间，并同步到大厅列表。
4. 玩家可创建房间或选择房间加入。
5. 未选中房间时，“加入房间”按钮置灰。
6. 创建房间或加入房间后进入房间界面。
7. 房间中存在房主。
8. 只有所有有效玩家都准备好后，房主才能点击开始游戏。
9. 点击开始游戏后，锁定座位和准备状态，倒计时 5 秒进入牌局。
10. 准备阶段允许普通成员准备、取消准备和换位置。
11. 庄家位置改为每局开局时随机选择。
12. 提升客户端文字显示清晰度。

## 2. 当前现状

当前版本中：

1. 服务端按 `room_id -> PokerRoom` 管理牌桌。
2. 客户端连接后直接进入单一房间。
3. 没有大厅列表。
4. 没有房主概念。
5. 没有房间创建 / 销毁同步机制。
6. 目前是“2 名及以上玩家 ready 后自动 3 秒开局”。

因此，本次设计的核心是把“单房间牌桌”升级为“大厅 + 多房间 + 房主控制”的结构。

## 3. 范围

本设计包含：

1. 大厅界面。
2. 房间列表刷新和同步。
3. 创建房间。
4. 加入房间。
5. 离开房间。
6. 房主机制。
7. 选座、换座、准备、取消准备。
8. 开始游戏按钮与 5 秒锁定倒计时。
9. 开局随机庄家。
10. 客户端文字清晰度优化。

本设计不包含：

1. 登录系统细节。
2. 账号密码体系。
3. 好友、邀请、匹配队列。
4. 聊天系统扩展。
5. 观战系统。

## 4. 大厅流程

### 4.1 大厅界面

登录成功后进入大厅界面，建议包含：

1. 当前玩家昵称
2. 当前连接状态
3. 刷新按钮
4. 房间列表
5. 创建房间按钮
6. 加入房间按钮

### 4.2 房间列表

每个房间条目建议展示：

1. 房间名称或房间 ID
2. 房主昵称
3. 当前人数，例如 `3/6`
4. 已准备人数
5. 房间状态：等待中 / 倒计时中 / 对局中

### 4.3 刷新逻辑

大厅刷新采用两种机制并存：

1. 玩家点击刷新按钮时，客户端主动向服务端请求最新大厅列表。
2. 服务端在房间创建、房间销毁、房间成员变化、房间状态变化时，主动推送大厅快照。

这样既满足手动确认，也能保证房间列表自动同步。

### 4.4 按钮规则

大厅按钮规则：

1. 未连接时，刷新 / 创建房间 / 加入房间均禁用。
2. 未选中房间时，加入房间按钮置灰。
3. 房间列表刷新后如果选中的房间消失，应自动取消选中态。

## 5. 房间生命周期设计

### 5.1 房间创建

1. 玩家点击“创建房间”。
2. 服务端创建房间对象。
3. 创建者自动成为房主。
4. 创建成功后客户端自动进入该房间。
5. 大厅列表同步新增该房间。

### 5.2 房间加入

1. 玩家在大厅中选中某个房间。
2. 点击“加入房间”。
3. 服务端校验房间存在且允许加入。
4. 加入成功后进入该房间界面。
5. 大厅列表同步更新该房间人数。

### 5.3 房间离开

1. 玩家点击“离开房间”返回大厅。
2. 服务端将其从房间成员中移除。
3. 若玩家已入座，需要同时离座。
4. 大厅列表同步更新人数。

### 5.4 房间销毁

建议规则：

1. 房间内没有任何成员时立即销毁。
2. 房间销毁后立即向大厅推送新列表。

## 6. 房主机制

### 6.1 房主定义

1. 创建房间的玩家默认为房主。
2. 房主信息需要在房间界面和大厅列表中展示。

### 6.2 房主转移

当房主离开房间时：

1. 若房间中仍有其他成员，服务端自动选择一名新房主。
2. 建议按加入顺序或座位顺序转移，优先保持规则简单稳定。
3. 若房间为空，则直接销毁房间。

### 6.3 房主权限

本阶段房主拥有以下特权：

1. 发起开始游戏

本阶段房主不额外拥有以下能力：

1. 强制踢人
2. 修改盲注
3. 修改座位数

## 7. 房间内准备阶段规则

### 7.1 选座

1. 未入座玩家可以点击任意空座位入座。
2. 已入座玩家在等待阶段可以切换到任意空座位。
3. 若已准备玩家换座，建议自动取消准备。

### 7.2 准备与取消准备

1. 已入座且筹码大于 0 的玩家可以准备。
2. 已准备玩家在等待阶段可以取消准备。
3. 未入座玩家不能准备。

### 7.3 房主开始游戏条件

房主的“开始游戏”按钮只有在满足以下条件时可点击：

1. 当前房间处于等待状态。
2. 没有正在进行中的牌局。
3. 已入座且筹码大于 0 的所有玩家都已准备。
4. 有效玩家数量至少为 2。

未满足条件时，“开始游戏”按钮置灰。

## 8. 开始游戏与锁定阶段

### 8.1 触发

1. 房主点击“开始游戏”。
2. 房间进入 5 秒倒计时。

### 8.2 倒计时阶段行为

倒计时期间：

1. 所有人不能换位置。
2. 所有人不能离座。
3. 所有人不能取消准备。
4. 房主不能重复点击开始游戏。

### 8.3 倒计时结束

1. 倒计时结束后正式发牌。
2. 房间从“等待状态”进入“对局状态”。
3. 后续沿用当前牌局逻辑。

### 8.4 异常取消

建议规则：

1. 如果房主离开房间，则取消倒计时并重新指定房主。
2. 如果有效玩家不足 2，则取消倒计时并回到等待状态。

## 9. 开局随机庄家

需求要求庄家位置改为开局随机选择，设计如下：

1. 每局开始前，从参与本局的有效座位中随机抽取一个 `dealer_seat`。
2. 小盲和大盲继续按当前德州规则相对庄家确定。
3. 本局结束后下一局重新随机。

这样可以直接满足当前需求，但它不是“长期轮转公平”模型。如果后续需要改为标准连续轮庄，可再迭代。

## 10. 服务端状态设计

建议把房间层状态和牌局层状态分开。

### 10.1 房间层状态

1. `OPEN`
2. `STARTING`
3. `PLAYING`

### 10.2 牌局层状态

继续保留当前：

1. `WAITING`
2. `PREFLOP`
3. `FLOP`
4. `TURN`
5. `RIVER`
6. `SHOWDOWN`
7. `HAND_COMPLETE`

建议映射：

1. `OPEN` 对应房间等待准备
2. `STARTING` 对应 5 秒锁定倒计时
3. `PLAYING` 对应 `PREFLOP` 到 `HAND_COMPLETE`

## 11. 协议设计建议

当前协议不足以表达大厅和房间管理。建议新增以下能力。

### 11.1 大厅相关客户端事件

1. `ListRooms`
2. `CreateRoom`
3. `JoinRoomById`
4. `LeaveRoom`

### 11.2 房间相关客户端事件

1. `ChangeSeat`
2. `SetReady`
3. `StartHand`

说明：

1. 可以继续复用 `SetReady`。
2. `StartHand` 的语义建议从“立即开始一手牌”调整为“房主发起开始流程”。

### 11.3 服务端事件

1. `LobbySnapshot`
2. `RoomStateSnapshot`
3. `RoomClosed`

### 11.4 房间快照建议新增字段

1. `owner_player_id`
2. `room_status`
3. `starting_countdown_seconds`
4. `member_count`
5. `ready_count`

## 12. 客户端界面与文字清晰度

本需求明确提到当前文字“分辨率太低，很模糊”，因此房间系统设计中同时纳入客户端 UI 清晰度改造。

### 12.1 字号调整

建议整体上调字号：

1. 常规字体：`19 -> 22`
2. 小字体：`15 -> 18`
3. 标题字体：`30 -> 36`
4. 牌面字体：`22 -> 26`

### 12.2 字体选择

建议优先顺序：

1. `Microsoft YaHei UI`
2. `Microsoft YaHei`
3. `Noto Sans CJK SC`

### 12.3 高 DPI 支持

建议在客户端初始化阶段启用高 DPI 感知，避免 Windows 对窗口做模糊缩放。

### 12.4 列表可读性

房间列表和房间成员列表建议：

1. 增加行高
2. 提高文字对比度
3. 增加选中高亮
4. 保证小字号中文仍清晰可读

## 13. 验收标准

满足以下条件即可视为大厅与房间系统达标：

1. 登录后进入大厅界面。
2. 大厅可显示房间列表。
3. 点击刷新可拉取最新房间列表。
4. 创建房间后自动进入房间。
5. 房间无人时自动销毁并从大厅消失。
6. 未选中房间时，“加入房间”按钮置灰。
7. 加入房间后进入房间界面。
8. 房间界面可展示房主。
9. 准备阶段非房主成员可准备、取消准备、换位置。
10. 只有所有有效玩家准备完成时，房主才能开始游戏。
11. 点击开始游戏后进入 5 秒倒计时。
12. 倒计时期间不能换位置，不能取消准备。
13. 倒计时结束后进入对局。
14. 每局庄家为随机选择。
15. 文字清晰度相比当前版本明显提升。

## 14. 推荐结论

推荐把大厅与房间系统作为独立一层实现，位于“登录”和“牌局核心规则”之间。这样既能复用现有 `PokerRoom` 的牌局逻辑，也能把房间创建、房主控制、准备开局和列表同步这些用户可感知能力补完整。
