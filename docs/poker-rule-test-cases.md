# 德州扑克规则与交互检查用例

本文档把当前版本需要长期守住的规则和客户端关键交互整理成自然语言用例。它不替代自动化测试，而是给 `tests/` 和 `tools/check_rules.py` 提供一份可对照、可复核的业务语义。

## 1. 适用范围

- 房间内 2 至 6 人无限注德州扑克对局。
- 服务端状态机、牌型评估、主池/边池结算。
- `pygame` 客户端的关键交互可用性。

## 2. 规则用例

### RC-01 少于两名准备玩家时不能开局

- 场景：房间内只有一名已入座且准备完成的玩家。
- 操作：尝试开始一手牌。
- 预期：
  - 服务端拒绝开局。
  - 返回“至少需要两名准备玩家”的错误。

### RC-02 单挑时庄家下小盲并先行动

- 场景：只有两名玩家参与。
- 操作：开始一手牌。
- 预期：
  - 庄家承担小盲。
  - 另一名玩家承担大盲。
  - 翻牌前由庄家先行动。

### RC-03 面对下注时不能过牌

- 场景：当前玩家尚未跟到本轮最高下注。
- 操作：执行 `CHECK`。
- 预期：
  - 服务端拒绝该动作。
  - 当前行动位保持不变。

### RC-04 加注不能低于最小加注额

- 场景：当前最小加注额已经形成。
- 操作：以低于 `current_bet + min_raise` 的目标额执行 `RAISE`。
- 预期：
  - 服务端拒绝动作。
  - `current_bet` 和 `min_raise` 不变。

### RC-05 短码全下不会错误改变最小加注额

- 场景：短码玩家剩余筹码不足以构成完整加注。
- 操作：执行 `ALL_IN`。
- 预期：
  - 当前跟注线可被抬高到该玩家的全下额。
  - `min_raise` 不会被缩小。

### RC-06 其余玩家弃牌后应直接赢池

- 场景：一手牌进行中，只剩一名未弃牌玩家。
- 操作：其余玩家依次弃牌。
- 预期：
  - 本手立刻结束。
  - 不进入摊牌。
  - 存活玩家直接获得全部底池。

### RC-07 所有可行动玩家完成本轮动作后才进入下一街

- 场景：翻牌后多人仍可继续行动。
- 操作：只有第一名玩家执行一次 `CHECK`。
- 预期：
  - 牌局仍停留在当前街。
  - 行动位移交给下一名合法玩家。

### RC-08 摊牌时自动从七张牌中选出最优五张

- 场景：玩家两张手牌加五张公共牌能组成多种五张组合。
- 操作：进入摊牌比较。
- 预期：
  - 系统自动选出最强五张牌。
  - 比较结果符合标准德州扑克牌型优先级。

### RC-09 A-2-3-4-5 识别为轮顺

- 场景：七张牌可组成 `A-2-3-4-5`。
- 操作：执行牌型评估。
- 预期：
  - 被识别为顺子。
  - 顺子高张按 5 计算。

### RC-10 同对子时由踢脚决定胜负

- 场景：两名玩家共享同一对子，但踢脚不同。
- 操作：进入摊牌比较。
- 预期：
  - 踢脚较大的玩家获胜。
  - 不会被错误判成平分底池。

### RC-11 边池只允许有资格玩家争夺

- 场景：至少三名玩家参与，其中一名短码全下，另外玩家继续追加筹码。
- 操作：进入摊牌结算。
- 预期：
  - 主池由所有贡献者组成。
  - 边池只允许对该层投入足够筹码的玩家参与争夺。
  - 短码玩家不能赢取自己未覆盖的边池。

### RC-12 弃牌玩家保留贡献但不能赢池

- 场景：某玩家先投入筹码，随后弃牌。
- 操作：其他玩家完成摊牌。
- 预期：
  - 弃牌玩家的历史贡献仍保留在底池中。
  - 弃牌玩家不能成为任何底池的赢家。

### RC-13 平分底池时总筹码变化守恒

- 场景：两名或多名玩家牌力完全相同。
- 操作：进入摊牌并分池。
- 预期：
  - 底池按规则平分。
  - 本手所有玩家的筹码变化总和为 0。

## 3. 客户端交互用例

### UI-01 等待阶段只允许准备，不允许对局动作

- 场景：玩家已入座，房间还在等待阶段。
- 操作：观察客户端按钮状态。
- 预期：
  - “准备/取消准备”按钮可用。
  - “弃牌/过牌/跟注/加注/全下”全部禁用。

### UI-02 面对下注时禁用过牌并启用跟注

- 场景：轮到自己，且自己的已投入小于当前下注。
- 操作：观察客户端动作按钮。
- 预期：
  - “过牌”禁用。
  - “跟注”启用。
  - 若筹码足够形成合法目标额，“加注”启用。

### UI-03 不面对下注时启用过牌并禁用跟注

- 场景：轮到自己，且自己的已投入已经等于当前下注。
- 操作：观察客户端动作按钮。
- 预期：
  - “过牌”启用。
  - “跟注”禁用。

### UI-04 结算结果会在侧边栏展示

- 场景：上一手已完成，快照中包含 `last_hand_result`。
- 操作：客户端刷新界面。
- 预期：
  - 侧边栏显示上一手赢家。
  - 侧边栏显示上一手手局 ID。
  - 侧边栏显示筹码变化摘要。

```powershell
python tools\check_rules.py
```

```powershell
python -m unittest discover -s tests -v
```
