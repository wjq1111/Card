# Texas Holdem Online 产品需求文档

## 1. 文档目标

本文档描述当前版本 TexasHoldemOnline 的用户可见行为、客户端交互要求、房间系统约束和基本验收标准。

本阶段目标是交付一个可运行的在线德州扑克牌桌体验，包含：

1. 登录界面
2. 大厅房间列表
3. 创建房间与加入房间
4. 房间内选座、准备、开始游戏
5. 5 秒开局倒计时锁定
6. 完整的一手无限注德州扑克牌局

## 2. 当前范围

### 2.1 本阶段必须完成的能力

1. 玩家启动客户端后先进入登录界面。
2. 玩家使用默认用户名 `Playerxxx` 或自行输入用户名。
3. 登录成功后进入大厅。
4. 大厅可刷新房间列表。
5. 玩家可创建房间。
6. 玩家可选择房间并加入。
7. 空房间会被服务端自动销毁。
8. 房间内支持入座、换座、离座、准备、取消准备。
9. 房主在所有有效玩家准备完成后可点击开始游戏。
10. 开始游戏后进入 5 秒倒计时，期间禁止换座和取消准备。
11. 倒计时结束后进入牌局。
12. 牌局支持 `FOLD`、`CHECK`、`CALL`、`RAISE`、`ALL_IN`。
13. 支持 Flop / Turn / River / Showdown / Hand Complete 完整流程。
14. 支持提前弃牌获胜、摊牌比牌、主池与边池结算。
15. 客户端文字显示清晰度较旧版明显提升。
16. 房主可在开局前向房间添加服务端托管 bot，bot 自动入座、自动准备，并在轮到自己时自动行动。
17. 服务端 bot 的加注金额应优先使用常见档位与规整筹码粒度，避免 `147` 这类明显不自然的散注。

### 2.2 本阶段不在验收范围内的能力

1. 账号密码系统
2. 好友与邀请
3. 自动匹配大厅
4. 商店、排行、充值
5. 观战模式
6. 完整断线重连体验
7. 房间聊天扩展

## 3. 用户角色

### 3.1 玩家

玩家需要能够：

1. 输入服务器地址和用户名登录
2. 在大厅查看和刷新房间列表
3. 创建房间
4. 选择房间并加入
5. 在房间内入座、换座、准备和取消准备
6. 在轮到自己时执行合法牌局动作
7. 在牌局结束后看到结果和筹码变化

### 3.2 服务端

服务端是权威裁判，负责：

1. 维护大厅和房间列表
2. 维护房主与房间生命周期
3. 校验座位、准备和开始游戏条件
4. 维护牌局状态、发牌、下注推进与结算
5. 向大厅广播房间列表，向房间成员广播房间快照

## 4. 端到端业务流程

### 4.1 登录

流程：

1. 玩家打开客户端。
2. 客户端显示服务器地址和用户名输入框。
3. 用户名默认值为 `Playerxxx`。
4. 玩家点击“进入大厅”。
5. 服务端返回 `player_id` 和 `reconnect_token`。
6. 客户端进入大厅。

验收要求：

1. 用户名不能为空。
2. 登录成功后不能直接进入房间。
3. 登录失败时客户端有明确错误提示。

### 4.2 大厅

流程：

1. 玩家进入大厅后看到房间列表。
2. 玩家可点击刷新按钮拉取最新房间列表。
3. 玩家可点击创建房间。
4. 玩家可选中某个房间后点击加入房间。

验收要求：

1. 未选中房间时加入房间按钮置灰。
2. 房间创建、房间销毁、房间成员变化应能反映到大厅列表。
3. 房间无人时服务端销毁房间。

### 4.3 房间等待阶段

流程：

1. 玩家创建房间或加入房间后进入房间界面。
2. 房间内显示房主、成员、座位和准备状态。
3. 未入座玩家可选择空座位入座。
4. 已入座玩家在等待阶段可更换到其他空座位。
5. 已入座且筹码大于 0 的玩家可准备或取消准备。

验收要求：

1. 已占用座位不能再次入座。
2. 倒计时开始前允许换座和取消准备。
3. 倒计时开始后禁止换座和取消准备。

### 4.4 开始游戏

流程：

1. 房主点击开始游戏。
2. 服务端校验：
   - 房间内有效玩家至少 2 人
   - 所有有效玩家都已准备
3. 校验通过后进入 5 秒倒计时。
4. 倒计时结束后正式开始当前手牌。

验收要求：

1. 非房主不能发起开始游戏。
2. 未满足条件时开始游戏按钮置灰或服务端拒绝。
3. 倒计时期间玩家不能换座，不能取消准备。

### 4.5 开局与庄家

流程：

1. 每局开始时，从本局参与玩家中随机选取庄家座位。
2. 双人局由庄家同时承担小盲并在翻牌前先行动。
3. 多人局按顺时针确定小盲和大盲。

验收要求：

1. 每局 `dealer_seat` 在有效参与玩家中随机产生。
2. 小盲、大盲、当前行动位广播正确。

### 4.6 下注流程

支持动作：

1. `FOLD`
2. `CHECK`
3. `CALL`
4. `RAISE`
5. `ALL_IN`

服务端规则要求：

1. 只有当前行动位玩家可以操作。
2. 面对下注时不能 `CHECK`。
3. `RAISE` 目标额不能低于 `current_bet + min_raise`。
4. `RAISE` 不能超过玩家可用筹码形成的总下注额。
5. 短码 `ALL_IN` 若未形成完整加注，不应错误缩小 `min_raise`。

客户端交互要求：

1. 非自己回合时动作按钮禁用。
2. 客户端按快照禁用明显非法动作。
3. 即使客户端已做禁用，服务端仍是最终裁判。

### 4.7 公共牌推进

流程：

1. Preflop 完成后发 3 张 Flop。
2. Flop 完成后发 1 张 Turn。
3. Turn 完成后发 1 张 River。
4. River 完成后进入 Showdown。

验收要求：

1. 公共牌数量按 `0 -> 3 -> 4 -> 5` 推进。
2. 本轮下注完成前不能提前进入下一街。
3. 所有人全下时服务端可自动发完后续公共牌并结算。

### 4.8 提前获胜与结算

流程：

1. 若任意时刻只剩一名未弃牌玩家，则该玩家直接赢得底池。
2. River 后所有存活玩家按德州规则比较牌型和踢脚。
3. 服务端依据玩家总投入拆分主池和边池并发放奖励。

验收要求：

1. 弃牌玩家不能赢得任何奖池。
2. 总筹码守恒。
3. 结果能反映到客户端的上一手结果区域。

## 6. 客户端 UI / UX 要求

### 6.1 页面结构

客户端至少包含三个页面状态：

1. 登录页
2. 大厅页
3. 房间页

### 6.2 登录页

必须包含：

1. 服务器地址输入框
2. 用户名输入框
3. 进入大厅按钮
4. 状态提示文字

### 6.3 大厅页

必须包含：

1. 当前玩家信息
2. 房间列表
3. 刷新按钮
4. 创建房间按钮
5. 加入房间按钮

### 6.4 房间页

必须包含：

1. 房间信息
2. 房主信息
3. 座位区
4. 成员列表
5. 准备按钮
6. 开始游戏按钮
7. 离开房间按钮
8. 对局动作按钮
9. 加注金额输入框，允许玩家输入本次“加注到”的目标总下注额
10. 桌内玩家位应展示真实牌图资源，不再用 `6H` 这类临时文本替代
11. 未弃牌玩家在自己的座位区域内应直观展示两张牌
12. 未翻开的牌必须使用牌背图展示
13. 玩家本轮已下注额应在玩家位旁单独标注，不与其他状态混排
14. 开局后不再在底部重复展示 `座位 1` 到 `座位 6` 的按钮行
15. 房间页布局必须随窗口分辨率变化保持可读和可操作
16. 客户端提供 GM 调试快捷键，为自己增加 2000 筹码
17. 默认窗口尺寸提升到 `1920x1080`
18. 对局中的提示信息改为顶部弹窗，显示约 2 秒后自动消失
19. 右侧最近日志需要自动换行，并以中文展示用户可见动作
20. bot 在每次执行操作前需要额外等待约 1 秒，避免动作瞬发
21. 服务端需要为每一手牌保留结构化单手日志，能够按 `hand_id` 对指定牌局进行明确回放，至少覆盖起手牌、盲注位、逐街公共牌、每一步动作、摊牌/弃牌结果与筹码变化。

### 6.5 文字清晰度

客户端需要：

1. 提高基础字号
2. 优先使用清晰的中文字体
3. 避免整屏低分辨率放大造成的模糊
4. 尽可能启用高 DPI 感知

## 7. 非功能要求

1. 服务端规则计算必须是权威来源。
2. 客户端异常输入不能破坏房间状态。
3. 房间创建、销毁和成员变更需要与大厅同步。
4. 自动化测试应覆盖房间等待阶段和客户端关键交互。

## 8. 自动化验收标准

以下命令应通过：

```powershell
python tools\generate_grpc.py
python -m unittest discover -s tests -v
python -m compileall src tools tests
```

至少应覆盖：

1. 房主发起倒计时开始游戏
2. 倒计时结束后进入牌局
3. 随机庄家与盲注位置计算
4. 房间结果回到等待状态
5. 客户端登录页、大厅页、房间页关键按钮状态
6. 客户端对局动作按钮启用 / 禁用逻辑

## 9. 后续迭代建议

建议留到下一阶段：

1. 完整断线重连 UX
2. 房间聊天可视化
3. 房间配置选项
4. 更丰富的大厅筛选与排序
5. 真正的账号系统
